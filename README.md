# AdaptiveTraffic

**Адаптивное управление городским перекрёстком.** Школьный исследовательский
проект секции «Инновации умного города»: разработка и исследование алгоритма
управления светофорным объектом при неравномерном транспортном потоке.

Цель — создать объяснимый контроллер и честно сравнить его с фиксированным
циклом. Гипотеза: очередь и ожидание помогают при неравномерном потоке,
а увеличение минимального зелёного при больших близких очередях уменьшает
потери на переключениях. Алгоритм не обязан выигрывать в каждом сценарии.

## V3: четыре физических светофора и Web Serial

Существующие FIXED / QUEUE_ONLY / ADAPTIVE V1 / ADAPTIVE V2 и научная модель
сохранены. Новый раздел **«Физический макет»** передаёт решение Python на Arduino
Uno R3 через браузерный USB Web Serial; физическая кнопка возвращает запрос
пешехода в ту же Simulation. Сервер может быть локальным или удалённым.

`Python Simulation → FastAPI → браузер → USB Serial → Uno → 4 светофора`.
Четыре направления отображают две совместимые фазы NS/EW. Нужны **14 LED,
14 отдельных резисторов 1 кОм и одна кнопка**, без датчиков и физических машин.

Начните с [подробной инструкции сборки](hardware/README_RU.md),
[электрических расчётов и распиновки](hardware/WIRING.md),
[SVG-схемы](hardware/wiring.svg) и [Serial-протокола](hardware/PROTOCOL.md).
Прошивка: [AdaptiveTrafficArduino.ino](hardware/arduino/AdaptiveTrafficArduino/AdaptiveTrafficArduino.ino).

После загрузки прошивки: Chrome/Chromium на компьютере, HTTPS или localhost →
«Физический макет» → «Подключить Arduino» → выбрать источник/алгоритм →
«Синхронизировать и запустить ×1». Алгоритм должен присутствовать в выбранной
сессии; в Compare можно включить все четыре и выводить на Uno один.
Синхронизация **перезапускает модели и очищает ручные события**, выдерживает
ALL_RED 4 с. На сайте показана последняя подтверждённая фаза, а при разрыве —
UNKNOWN. Пауза/смена контроллера/скрытие вкладки приостанавливают вывод;
ускорение блокируется, «До конца» сначала устанавливает ALL_RED.

Uno проверяет порядок переходов и реальные интервалы 3/1/10/3 с независимо
от браузера. Watchdog 2,5 с закрывает зелёные на питаемой плате. До setup()
программная защита не действует; при снятии USB-питания лампы гаснут. Это
учебный макет, не управление реальным дорожным оборудованием.
Без Arduino весь существующий сайт продолжает работать.

### Хостинг

Подготовлены Dockerfile, amvera.yaml и отдельный production-запуск:
`python -m adaptive_traffic.serve` (HOST/PORT и политика из окружения).
Для веб-контейнера достаточно `requirements-web.txt`; полный requirements.txt
сохранён для GUI, тестов и научных графиков. Один процесс/одна реплика.

[Amvera: пошаговая настройка](docs/DEPLOY_AMVERA_RU.md) ·
[Linux VPS: Docker, HTTPS и лимиты](docs/DEPLOY_VPS_RU.md) ·
[Текущий статус публикации](docs/AMVERA_STATUS_RU.md).
На публичном сервере: ограниченные сессии/запросы/длительность, лаборатория
по ADMIN_TOKEN, секреты только в окружении. HTTPS завершается на доверенном
reverse proxy; wildcard CORS не используется. Хостинг не куплен, адрес сайта
не создан. USB подключается к ноутбуку пользователя, а не к серверу.

Проверка production через реальные HTTP-запросы:
`python tools/check_production.py --stress` (8 сессий, 4 контроллера, лаборатория,
измерение памяти в Linux). После push в `main` workflow **Tests and production
container** также проверяет Docker при 500 МБ RAM / 0,25 CPU. Результат CI
подтверждает проверенный сценарий нагрузки, а не доступность сайта в Amvera.

## WEB DEMO

Локальная интерактивная лаборатория — основной демонстрационный интерфейс:
«Не верьте готовому графику — попробуйте сами».

Требования: Python **3.10+**, современный браузер, обычный ноутбук.
Node.js/npm, облако и база данных не нужны. Один процесс сервера.
Команды выполняются из корня проекта:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py --web
```

Windows PowerShell: `.venv\Scripts\Activate.ps1` вместо `source`.
Откройте **http://127.0.0.1:8000** — браузер также открывается автоматически.
Другой порт и запуск без автоматического открытия браузера:

```bash
python main.py --web --web-port 8080 --no-browser
```

При `python main.py --web` сервер слушает только `127.0.0.1`. Остановка — `Ctrl+C` в терминале.
После установки зависимостей всё работает **без интернета**: страницы,
скрипты, шрифты системы, Canvas, API и подготовленные результаты локальные.
Ссылка GitHub требует интернета. CDN, внешней аналитики, регистрации нет.

### Попробовать самим / Try yourself

1. На главной нажмите **«Попробовать самим»**. Откроется NS_HEAVY, seed 42,
   ADAPTIVE V2, 180 секунд генерации.
2. **«Пробка NS»** добавляет по 10 машин на NORTH и SOUTH. Для EW аналогично.
   Подходы имеют отдельные кнопки +1 / +5 / +10.
3. Нажмите **«Пешеходный запрос»**. Панель покажет запрос, ожидание и сигнал;
   во время PED_GREEN все автомобильные лампы красные.
4. **«Сравнить с FIXED»** воспроизводит тот же план и уже введённые события
   для FIXED и V2 до текущего модельного времени.
5. **«До конца»** быстро выполняет оставшиеся шаги Python без покадровой
   анимации и показывает таблицу, график и скачивание JSON.

Ручной ввод — **только демонстрационная функция**. Такие результаты помечены;
они не смешиваются с научными headless-экспериментами. События доступны до
конца генерации, максимум 1000 ручных автомобилей на сессию. Повторный
пешеходный запрос объединяется до конца текущего цикла.

### Simulator / Симулятор

Доступны FIXED, QUEUE_ONLY, ADAPTIVE V1 и ADAPTIVE V2; все 7 сценариев и CUSTOM.
CUSTOM задаёт постоянный поток NORTH/SOUTH/EAST/WEST в авто/мин, от 0 до 25.
Измените параметры и нажмите «Новый поток». Смена алгоритма и «Заново»
используют прежний объект TrafficPlan, но очищают ручные события и статистику.

Старт, пауза, скорости ×1/×5/×20/×100 меняют только частоту вызова `step()`.
Размер шага и модель обслуживания не меняются. Стенд/полный экран увеличивает
перекрёсток и элементы управления; CSS-режим работает и без Fullscreen API.

Метрики ожиданий во время работы относятся **только к уже обслуженным** машинам.
Очереди точные, но на рисунке видно максимум пять машин каждого подхода.
Проезды анимируются только по событиям Python; это не отдельная физика движения.
Текущие очереди показаны после последнего шага, а V2 debug — в момент принятия
последнего решения, с явной отметкой времени.

### Compare / Сравнение

По умолчанию FIXED vs ADAPTIVE_V2; флажками выберите любые **2–4** контроллера.
Им передаётся один неизменяемый TrafficPlan. Пешеходные нажатия и ручной ввод
поступают в одинаковый model time. После генерации отдельные drain-периоды
могут закончиться в разное время; завершённый контроллер больше не шагает.

После завершения: mean_wait, p95, очереди, полное время, число смен, доля
переходов, средний зелёный. Проценты сравнения вычисляет Python; положительный
процент означает улучшение. При нулевой базе процент не определён. Если запуск
не завершился, частичные метрики помечены и проценты преимущества не выдаются.

### Laboratory / Лаборатория

Выберите сценарий (или все 7), контроллеры, **1–50 seeds**, первый seed,
длительность генерации и необязательное расписание пешеходов, например `5, 60, 120`.
Для опыта на 10 seeds поставьте «Число seeds = 10», seed 42: это 42–51.
CUSTOM использует тот же воспроизводимый генератор, что обычные сценарии.

«Расширенные параметры» открывает только разрешённые поля: MIN_GREEN,
MAX_GREEN, MAX_WAIT, WAIT_EQUIVALENT, SWITCH_MARGIN и три параметра V2.
Проверяется неотрицательность, конечность, MIN_GREEN ≤ MAX_GREEN, сетка времени
и ratio в (0,1]. Эффективный минимум V2 ограничивается [MIN_GREEN, MAX_GREEN].
Есть сброс к исследованным значениям по умолчанию.

Один фоновый эксперимент за раз, прогресс — число завершённых запусков.
Результаты сохраняются в новую папку `results/web_<timestamp>_<id>/`:

- `results.csv` — реальные показатели каждого запуска;
- `diagnostics.csv` — причины смен, длительности, доля переходов;
- `metadata.json` — параметры, seeds, контроллеры, расписание, дата;
- `switches/` — журналы переключений;
- `analysis/` — средние, разброс, попарные сравнения и исключения.

Браузер показывает графики и скачивает CSV. Путь к папке отображается текстом;
API не запускает файловый менеджер и не принимает пути или shell-команды.
Сырые файлы сохраняются на диске после выключения сервера.

## Контроллеры и исследование V2

- **FIXED**: зелёный 30 с, жёлтый 3 с, общий красный 1 с.
- **QUEUE_ONLY**: приоритет = очередь; те же ограничения по времени, включая MAX_WAIT.
- **ADAPTIVE**: исходная V1 сохранена. Приоритет = `queue + oldest_wait / 10`.
  Порядок: MIN_GREEN → EMPTY_CURRENT → MAX_WAIT → MAX_GREEN → HIGHER_PRIORITY.
- **ADAPTIVE_V2**: отдельный контроллер. Если обе очереди ≥ **8** и отношение
  меньшего приоритета к большему ≥ **0,65**, эффективный минимум зелёного **30 с**;
  иначе обычные **10 с**. Затем те же проверки V1. При изменении нагрузки условие
  пересчитывается. Контроллер не знает названия сценария.

Выбрана одна из 18 разрешённых конфигураций на seeds 42–51. Затем проведён
holdout на seeds 100–119: 7 сценариев × 20 seeds × 4 контроллера = 560 запусков,
все завершены. После holdout настройки не менялись.

| Holdout: mean_wait, с | FIXED | V1 | V2 |
|---|---:|---:|---:|
| BALANCED_HIGH | 33,25 | 126,30 | 45,00 |
| RUSH_HOUR | 137,98 | 238,97 | 142,18 |

V2 заметно улучшил V1, но **в этих двух сценариях уступает FIXED**.
На остальных пяти holdout-сценариях mean_wait V2 не вырос.
Полный протокол, development, holdout, диагностика и ограничения:
[docs/adaptive_v2_research.md](docs/adaptive_v2_research.md).
Выбор: [docs/v2_selection.json](docs/v2_selection.json).
Сайт читает настоящую сводку [web/data/reference_results.json](web/data/reference_results.json),
включая seeds, config, дату и SHA-256 исходного CSV. Кнопка «Воспроизвести
эксперимент» запускает соответствующую серию через лабораторию.

## Headless: научные эксперименты

```bash
python main.py --controller fixed --scenario ns_heavy --seed 42
python main.py --controller queue_only --scenario ns_heavy --seed 42
python main.py --controller adaptive --scenario ns_heavy --seed 42
python main.py --controller adaptive_v2 --scenario ns_heavy --seed 42
python main.py --controller all --scenario all --runs 10 --seed 42 --output results/my_development
python -m adaptive_traffic.analyze results/my_development/results.csv
```

`--controller both` (также по умолчанию) сохраняет пару FIXED/ADAPTIVE.
`--controller all` теперь выбирает **все четыре**. `--scenario all` выбирает
все стандартные сценарии. Папка `--output` должна быть новой; перезаписи нет.
`--duration 1800` — время генерации, `--drain-timeout 1800` — дополнительный
предел обслуживания очередей. При незавершённом опыте CSV сохраняется с
`completed_successfully=False`, CLI возвращает 1.

```bash
python main.py --controller all --scenario ns_heavy --pedestrian-times 5 60 120 --output results/my_pedestrians
python main.py --controller all --scenario all --runs 20 --seed 100 --output results/my_holdout
python -m adaptive_traffic.analyze results/my_holdout/results.csv
```

Анализ совместим со старыми парами и тройками, а также четырьмя контроллерами.
Незавершённый или отсутствующий контроллер исключает весь scenario/seed.
`comparison.csv` сохраняет прежние поля FIXED/ADAPTIVE, когда оба присутствуют;
`pairwise_comparison.csv` содержит все пары. `summary.csv` — средние и выборочное
SD по seeds. Графики mean_wait, p95_wait, mean_queue, total_clearing_time
сохраняются в PNG/SVG. Полосы показывают SD, не доверительный интервал.
`--no-plots` отключает построение картинок.

## Pygame GUI сохранён

```bash
python main.py --visualize --controller adaptive_v2 --scenario ns_heavy --seed 42
```

Окно 1200×800. SPACE — пауза, R — заново, 1/2/3 — ×1/×5/×20,
P — пешеход, F/Q/A/V — FIXED/QUEUE_ONLY/V1/V2, ESC — выход.
GUI и веб переиспользуют `get_view_state()`. Pygame не импортируется при
headless-запусках или запуске веба. Если для вашей версии Python нет готового
pygame wheel, сборке нужны SDL2 и SDL2_ttf; обычно проще использовать Python
с доступным wheel. В текущем `.venv` pygame уже установлен.

## Тесты

```bash
pytest -q
```

Проверяются правила четырёх контроллеров, безопасные переходы, пешеходы,
воспроизводимость, CSV/анализ, API и ручные события. Legacy-fixture фиксирует
числовые результаты и SHA-256 каждого журнала для исходных трёх алгоритмов
на всех семи сценариях; отдельная проверка защищает исходный код их классов.
Новые тесты исполняют настоящее C++-ядро прошивки с виртуальными часами;
для них нужен `g++` (если его нет, эти проверки явно пропускаются).
Компиляция для платы отдельно:

```bash
arduino-cli core install arduino:avr
arduino-cli compile --fqbn arduino:avr:uno hardware/arduino/AdaptiveTrafficArduino
```

Дополнительная проверка Chromium/Web Serial через тот же C++-код:

```bash
pip install playwright
python -m playwright install chromium --only-shell
python tools/check_web_hardware.py
```

Это зависимость только проверки, не сайта. Она запускает и останавливает
собственный сервер на 8011, проверяет аппаратный режим примерно за две минуты
и сохраняет протокол в results/. Физическую USB-плату такой тест не заменяет.

Web-тесты используют FastAPI TestClient; ему нужны локальные сокеты между
потоками (в жёстком sandbox их запрет может потребовать запуска тестов вне него).

## Архитектура и ограничения

`TrafficPlan → Simulation + Controller + TrafficLight → presentation → FastAPI → Canvas`.
JavaScript рисует и отправляет команды; модель и показатели рассчитывает Python.
Сессии в памяти: до 32, удаляются после 30 минут без обращения; после перезапуска
сервера исчезают. Сведения о завершённых задачах живут до 2 часов, CSV остаются.
Большие серии занимают время на слабом ноутбуке; сервер поддерживает один
лабораторный эксперимент одновременно. Нет учётных записей и базы данных. Для публичной демонстрации предусмотрены
отдельные ограничения; это не сервис с гарантированным масштабированием.

Один перекрёсток, четыре направления, движение прямо. Шаг 1 с, интервал проезда
2 с на направление; нет разгона, поворотов, соседних перекрёстков, конечной
ёмкости очередей и ошибок датчиков. Редкие запросы защищены порогами, но при
перегрузке MAX_WAIT не гарантирует верхний предел ожидания каждого автомобиля.
Результаты нельзя переносить на реальную дорогу без отдельной проверки.

Подробнее: [алгоритмы](docs/algorithm.md), [модель и метрики](docs/simulation_model.md),
[локальный API](docs/web_api.md), [исследование V2](docs/adaptive_v2_research.md).
Генерируемые `results/`, виртуальное окружение, секретные `.env` и кэши исключены
из Git. Подготовленная небольшая сводка сайта хранится отдельно в `web/data/`.
