Диагностика согласуется с гипотезой потерь от частых переключений, но уточняет
её: доминирует MAX_WAIT, а не HIGHER_PRIORITY. При старых очередях обеих фаз
MAX_WAIT просит смену уже после MIN_GREEN; потеря обслуживания на переходах
усиливает накопление очереди. Это наблюдаемый механизм в данной модели,
не доказательство единственной причины в реальном дорожном движении.
RUSH_HOUR во второй половине предъявляет 72 авто/мин, превышая даже идеальную
суммарную пропускную способность 60 авто/мин без переходов при headway=2 с.

## План выбора, зафиксированный до holdout

V2 изменяет только эффективный минимум зелёного. Оба приоритета прежние:
`queue + oldest_wait / wait_equivalent`. При двух очередях не меньше порога
и min(priority)/max(priority) не меньше balance_ratio используется увеличенный
минимум, ограниченный [min_green, max_green]. Затем проверки V1 в прежнем
порядке: EMPTY_CURRENT, MAX_WAIT, MAX_GREEN, HIGHER_PRIORITY. При пустой текущей
очереди стабилизация отключается. Пешеходный timeout остаётся отдельным
ограничением после обычного MIN_GREEN, как у V1.

Development: только seeds 42–51, все 7 сценариев. Ровно 18 комбинаций:
порог 6/8/10, отношение 0.65/0.75, минимум 20/25/30 с.
Выбор: сначала конфигурации с улучшением обоих тяжёлых сценариев и guardrails
на остальных (mean <= max(V1*1.10, V1+2 с), p95 <= V1*1.15).
Среди прошедших минимизируем среднее двух отношений mean_wait V2/V1 для
BALANCED_HIGH и RUSH_HOUR. Если ни одна не проходит, выбираем минимальное
суммарное относительное превышение guardrails, затем тот же целевой показатель;
нарушения обязательно публикуем. Никакого дополнительного поиска.
После выбора фиксируем JSON параметров, затем единожды запускаем holdout
100–119 на всех сценариях и четырёх контроллерах. После holdout не настраиваем V2.

## Интерпретация

На holdout V2 снижает mean_wait относительно V1 на 64,37% в BALANCED_HIGH
и на 40,50% в RUSH_HOUR. Одновременно уменьшается доля переходов и растёт
средний зелёный. Это поддерживает гипотезу о потере обслуживания при слишком
частых сменах, включая обратную связь через MAX_WAIT.
Однако V2 проигрывает FIXED по mean_wait в этих сценариях на 35,36% и 3,04%.
Нельзя утверждать, что адаптивный алгоритм всегда выигрывает.

В остальных пяти сценариях holdout среднее не выросло: NS_HEAVY −0,16%,
EW_HEAVY −0,91%, CHANGING_FLOW −0,69%; BALANCED_LOW и MINOR_ROAD совпали с V1.
На development выбранная конфигурация также прошла все guardrails. Различия порядка долей процента не стоит трактовать
как уверенное преимущество без отдельной статистической проверки.

## Воспроизводимость

```bash
python main.py --controller all --scenario all --runs 20 --seed 100 --output results/my_holdout
python -m adaptive_traffic.analyze results/my_holdout/results.csv
```

Для точного запуска с зафиксированным JSON выбора:

```bash
python -m adaptive_traffic.research holdout results/v2_development_20261012 results/my_frozen_holdout
```

Полные файлы: `results/v2_holdout_20261012/`, включая diagnostics.csv и журналы.
Сводка сайта `web/data/reference_results.json` скопирована из настоящего
holdout, содержит конфигурацию, дату, seeds, все 28 групп и SHA-256 CSV и
selection.json. Её числа сформированы программно из CSV, не вручную.
`docs/v2_selection.json` хранит выбранный development-вариант.

## Ограничения

18 конфигураций и 10 development seeds — небольшой ограниченный поиск,
не доказательство оптимальности. Holdout содержит только 20 seeds и те же
семь типов потоков. Средние по seeds имеют равный вес; p95 усредняются по
отдельным запускам. В отчёте нет доверительных интервалов и проверки значимости.
Исследование выполнялось без пешеходных запросов; их корректность проверяют
тесты, но эффект интенсивного пешеходного спроса требует отдельного исследования.

Модель начинает с пустых очередей, идеальных датчиков и NS_GREEN, не учитывает
повороты, поведение водителей, ёмкость дорог и соседние светофоры. MAX_WAIT
не ограничивает задержку каждого автомобиля при перегрузке. Увеличенный
минимум может задержать редкий спрос до окончания эффективного минимума;
при сильной асимметрии стабилизация отключается. Пешеходный timeout имеет
приоритет после обычного MIN_GREEN, чтобы стабилизация не блокировала переход.
Это объяснимый алгоритм для исследования данной модели, а не «лучший светофор
вообще» и не готовое управление реальным оборудованием.
