# AdaptiveTraffic V3 на Amvera

Конфигурация готова; текущий статус доступа и проверок записан в
[отчёте публикации](AMVERA_STATUS_RU.md). Наличие файлов Docker само по себе
не означает, что сайт опубликован.
Arduino подключается к USB компьютера с браузером; серверу Serial-порт не нужен.

## Бюджет и выбор

На 25.10.2026 официальная страница указывает «Начальный»: 0,25 CPU, 500 МБ RAM,
5 ГБ SSD, 290 ₽/30 дней. Это кандидат в бюджет 150–300 ₽, а не гарантия
достаточной производительности под любой нагрузкой. «Пробный» за 170 ₽ имеет
100 МБ RAM — для Python и серии экспериментов слишком мало запаса; его не
рекомендуем для демонстрации. Перед оплатой проверьте актуальную цену и лимиты
в [тарифах Amvera](https://docs.amvera.ru/general/price.html).

## Подготовка источников и приложения

1. Проверьте локально `python -m pytest -q` и
   `python tools/check_production.py --stress`. После push в `main` GitHub Actions
   запускает тесты, собирает Docker и проверяет контейнер с лимитами 500 000 000
   байт RAM, без swap, с 0,25 CPU. Результат смотрите в Actions конкретного коммита.
2. В панели Amvera сначала найдите существующее оплаченное приложение и проверьте
   его регион, тариф, статус и право обновления. Используйте его, если это проект
   AdaptiveTraffic. Создание платного приложения или увеличение тарифа требует
   отдельного согласия владельца. Для приложения выберите Docker.
   В проекте уже есть `Dockerfile`, `.dockerignore`, `amvera.yaml`.
   Docker-образ использует Python 3.12, один Uvicorn-процесс и облегчённый
   `requirements-web.txt`; pygame/pytest/matplotlib для веба не нужны.
3. На вкладке «Репозиторий» подключите существующий
   `https://github.com/durovp/AdaptiveTraffic`, ветку `main`. Для автоматической
   интеграции используйте Fine-grained GitHub token с доступом только к этому
   репозиторию и разрешениями, показанными в текущем мастере Amvera. Токен
   вводится в панели, не в файлах проекта. Настройте webhook на push.
   [Официальная инструкция GitHub/webhooks](https://docs.amvera.ru/applications/git/webhooks.html)
4. Если GitHub пока не подключаете, загрузите исходные файлы через панель Code
   по инструкции интерфейса. Не загружайте `.git`, `.venv`, `.env`, `results/` и кэши.
5. `amvera.yaml` задаёт `containerPort: 8000` и постоянное хранилище `/data`.
   Docker CMD — `python -m adaptive_traffic.serve`. Не добавляйте несколько
   workers или реплик: состояние сессий хранится в памяти одного процесса.
   [Параметры Docker-развёртывания](https://docs.amvera.ru/applications/configuration/docker.html)

## HTTPS и переменные окружения

В настройках домена приложения добавьте предоставленный Amvera адрес и выберите
HTTPS. Дождитесь сертификата. Скопируйте **фактический** hostname из панели;
в примерах ниже `YOUR-HOST.amvera.io` — обозначение, не опубликованный адрес.
Amvera позволяет привязать домен и сертификат к HTTPS ingress.
[Сеть, домены и HTTPS](https://docs.amvera.ru/applications/configuration/network.html)

Укажите переменные среды в панели:

| Имя | Значение |
|---|---|
| TRAFFIC_ENV | production |
| HOST | 0.0.0.0 |
| PORT | 8000 |
| ALLOWED_HOSTS | YOUR-HOST.amvera.io,127.0.0.1,localhost |
| ALLOWED_ORIGINS | https://YOUR-HOST.amvera.io |
| RESULTS_DIR | /data/results |
| MAX_SESSIONS | 8 |
| SESSION_TTL | 900 |
| MAX_DURATION | 600 |
| ADMIN_TOKEN | секретный случайный ключ не менее 32 символов |
| FORWARDED_ALLOW_IPS | 127.0.0.1 либо подтверждённые адреса/CIDR прокси Amvera |

ALLOWED_HOSTS — точные имена без схемы и wildcard; ALLOWED_ORIGINS — точные
HTTPS origins без пути. Публичные POST без Origin отклоняются. API не включает
CORS для сторонних сайтов. Проверка Origin использует явный список, поэтому
работает и при завершении TLS на внешнем reverse proxy.

Сгенерировать ADMIN_TOKEN на своём компьютере:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Скопируйте ключ в **секретную переменную** панели. Этот ключ не имеет отношения
к GitHub token или USB-разрешению. Без ADMIN_TOKEN лаборатория на публичном
сервере закрыта; симулятор, Compare и зафиксированные результаты доступны.
Для лаборатории ключ вводится в поле администратора на странице; передаётся
в Authorization, не сохраняется в localStorage, URL или cookie.

Не ставьте `FORWARDED_ALLOW_IPS=*` автоматически. Уточните доверенные proxy CIDR
у провайдера. Если оставить loopback, все запросы прокси могут учитываться как
один клиент rate limiter: это консервативно и может раньше ограничивать доступ.
Глобальный лимит действует независимо от клиентского IP. Не доверяйте
произвольным X-Forwarded-For от пользователей.

Контейнер работает с UID 10001. Проверьте, что подключённое постоянное хранилище
даёт этому пользователю право создавать `/data/results`. При проблеме с правами
настройте владельца/права тома средствами панели/поддержки; не открывайте весь
контейнер на запись. Как явно временный вариант можно использовать
`RESULTS_DIR=/tmp/results`, понимая, что CSV исчезнут при пересоздании контейнера.

## Запуск и проверки

Запустите сборку. В логах ожидается Uvicorn на 0.0.0.0:8000. Проверяйте
ошибки переменных, права `/data`, RAM и перезапуски. Адрес берётся только из
панели. На фактическом адресе:

```bash
curl -f https://YOUR-HOST.amvera.io/healthz
curl -f https://YOUR-HOST.amvera.io/api/project
curl -f https://YOUR-HOST.amvera.io/api/scenarios
```

healthz возвращает `{"status":"ok"}`. Docker HEALTHCHECK обращается к тому же
маршруту локально с разрешённым Host; при настройке платформенной HTTP-пробы
также задайте разрешённый Host, иначе TrustedHost вернёт 400.

Проверьте в браузере: новый поток, шаги, Compare, «До конца», лаборатория
без ключа (отказ) и с ключом (небольшая серия), скачивание CSV. Не начинайте
с полного holdout на маленьком тарифе.

Затем в Chrome/Chromium на школьном ноутбуке откройте сайт как отдельную вкладку
по HTTPS, подключите Uno, закройте Serial Monitor, нажмите «Физический макет» →
«Подключить Arduino», выберите USB-порт. Доступ даётся браузеру ноутбука, не
Amvera. Выполните синхронизацию ×1 по [руководству макета](../hardware/README_RU.md).
Браузер должен поддерживать Web Serial, secure context и запрос по действию
пользователя. [Web Serial в Chrome](https://developer.chrome.com/docs/capabilities/serial)

## Лимиты, обновления и эксплуатация

Production: 8 сессий, TTL 15 минут, генерация до 600 с; запросы до 16 КиБ;
token bucket 600 единиц/мин на IP, 1800 глобально. Создание сессии/сравнения
стоит 30, finish 60, остальные API-запросы 1. Не более двух одновременных
мутаций API; одна лаборатория, максимум 560 запусков за задачу, лимит времени
120 с проверяется между отдельными запусками. Лаборатория требует ключ;
при превышении 100 МиБ сохранённых файлов новые задачи отклоняются.
CSV не удаляются автоматически. Ограничения CPU/RAM задаёт тариф.
Подсчёт файлов включает вложенные `switches/` и `analysis/`. Порог проверяется
перед новой задачей: уже запущенная серия может немного превысить его.
Полное тело запроса должно поступить не позднее 5 секунд.

Длинные исследования выполняйте локально headless и сохраняйте реальные CSV.
Если нужен публичный эксперимент крупнее лимита, сначала оцените ресурсы и
только затем меняйте политику сервера. Это не защита от распределённой DDoS-атаки:
при открытой публикации полезны дополнительные ограничения ingress провайдера.

После настройки GitHub-интеграции обновление main через webhook запускает сборку.
До подключения webhook один лишь push в GitHub не обновляет Amvera.
Перезапуск очищает активные сессии/дескрипторы задач; файлы в постоянном томе
остаются. Архивируйте CSV вручную; завершение лаборатории при остановке
проверяется между опытами. После обновления повторите healthz, симулятор,
небольшую лабораторию и USB-синхронизацию. При сбое откатите версию в панели,
сохраняя том результатов.

## Доступ для следующего запуска Codex

Официальный MCP: `https://openmcp.msk0.amvera.ru/mcp` для Москвы или
`https://openmcp.waw0.amvera.ru/mcp` для Варшавы. Используйте регион существующего
приложения. MCP требует Bearer-токен из личного кабинета Amvera.
[Документация Amvera MCP](https://docs.amvera.ru/MCP/doc-mcp-ru.html)

Подключение Codex без записи токена в проект:

```bash
codex mcp add amvera-moscow --url https://openmcp.msk0.amvera.ru/mcp --bearer-token-env-var AMVERA_MCP_TOKEN
read -rsp 'Amvera MCP token: ' AMVERA_MCP_TOKEN; echo
export AMVERA_MCP_TOKEN
codex
```

В этой рабочей среде первая команда уже выполнена. Токен вводится скрыто в
терминале; не вставляйте его в чат, командную строку аргументом или файл проекта.
CLI Codex или полностью перезапущенный IDE должен наследовать эту переменную;
`export` во встроенном терминале не меняет окружение уже работающего IDE.
[Настройка MCP в Codex](https://developers.openai.com/codex/mcp/)

Альтернатива без перезапуска IDE — официальный CLI Amvera:

```bash
amvera login
amvera get projects
```

Пароль вводится только в интерактивном терминале. Не передавайте его через
`--password`, историю команд или переписку. В среде подготовки бинарник доступен
как `/tmp/adaptive-amvera-cli/amvera`; если временная папка очищена, используйте
[официальную установку CLI](https://docs.amvera.ru/general/cli.html).

После авторизации следующий агент должен прочитать этот документ и отчёт,
получить реальные проекты/тариф/домены, проверить оплату, задать точные Host и
Origin, права `/data/results`, затем загрузить разрешённый commit и проверить
логи сборки/запуска и публичный HTTPS. Не создавать дубликат приложения.
При отсутствии оплаченного приложения сначала представить владельцу конкретный
тариф и сумму; до подтверждения платное приложение не запускать.
