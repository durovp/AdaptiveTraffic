# AdaptiveTraffic Serial Protocol 1

USB CDC/UART, **115200 baud, 8N1**, ASCII, одна команда на строку LF
(CR перед LF разрешён). D0/D1 заняты Serial. Нет JSON, динамического String
и сторонних библиотек. Реализация: `arduino/AdaptiveTrafficArduino/TrafficProtocol.h`.
Arduino не рассчитывает очереди и не выбирает алгоритм управления.

## Соединение и команды

После открытия порта браузер ждёт 1800 мс для обычного сброса Uno.
Далее обмен:

```text
HELLO
READY,ADAPTIVETRAFFIC,1,3000,1000,10000,3000
SYNC,1
ACK,1,SAFE_ALL_RED
PING,2
ACK,2,SAFE_ALL_RED
```

READY идентифицирует прошивку, версию и интервалы в миллисекундах:
yellow=3000, all_red=1000, ped_green=10000, ped_clearance=3000.
Это интервалы существующего Python Config. Web не позволяет менять их;
при изменении в коде нужно согласованно обновить версию протокола/прошивку.

После **не менее 4000 мс** от SYNC, при свежих PING:

```text
STATE,10,0,NS_GREEN
ACK,10,NS_GREEN
STATE,11,1000,NS_GREEN
ACK,11,NS_GREEN
```

Номера в примере пропущены только для краткости: на проводе каждое новое сообщение
имеет ровно предыдущий номер +1. HELLO не нумеруется, закрывает зелёные и сбрасывает
счётчик. После него первая команда имеет номер 1. Номера — uint32 от 1;
переполнение требует HELLO. STATE содержит модельное время в мс и имя фазы.
Первая STATE после SYNC допускает только время 0 и NS_GREEN: веб явно
перезапускает выбранную сессию/сравнение перед подключением к физическому выводу.
Последующие времена не уменьшаются и растут максимум на 1000 мс. Событие
пешехода может изменить цель ALL_RED без продвижения времени.

| Команда | Результат |
|---|---|
| HELLO | ALL_RED, сброс протокола, READY |
| SYNC,seq | ALL_RED, начало защитного ожидания 4 с |
| STATE,seq,tick_ms,phase | Проверить время и переход, применить GPIO, затем ACK |
| PING,seq | ACK текущей физической фазы; обновить watchdog |
| STOP,seq | Немедленно убрать зелёные, автомобильный и пешеходный RED; снять SYNC |

Один запрос в работе. ACK содержит номер и **применённую** фазу, не только
эхо запроса. GPIO обновляются до ACK. Ожидание ACK — 1600 мс, одна повторная
отправка идентичной строки через 800 мс. Прошивка хранит последнюю успешную
строку/ACK: точный повтор возвращает прежний ACK, не запускает фазу заново.
Тот же номер с другим содержимым, старый номер или пропуск — ERROR и ALL_RED.
Старые ответы не принимаются как подтверждения новой команды.

## Независимые проверки Arduino

| Текущее состояние | Разрешённое следующее | Минимальное реальное время текущего |
|---|---|---:|
| SAFE_ALL_RED после SYNC | NS_GREEN | 4000 мс |
| NS_GREEN | NS_YELLOW | решение о конце зелёного делает Python |
| EW_GREEN | EW_YELLOW | решение о конце зелёного делает Python |
| NS_YELLOW | ALL_RED_TO_EW или ALL_RED_TO_PED | 3000 мс |
| EW_YELLOW | ALL_RED_TO_NS или ALL_RED_TO_PED | 3000 мс |
| ALL_RED_TO_EW | EW_GREEN | 1000 мс |
| ALL_RED_TO_NS | NS_GREEN | 1000 мс |
| ALL_RED_TO_EW/NS | ALL_RED_TO_PED | можно немедленно; начало красного сохраняется |
| ALL_RED_TO_PED | PED_GREEN | 1000 мс |
| PED_GREEN | PED_CLEARANCE | 10000 мс |
| PED_CLEARANCE | ALL_RED_AFTER_PED | 3000 мс |
| ALL_RED_AFTER_PED | NS_GREEN или EW_GREEN | 1000 мс |

Повторение той же фазы допустимо, её таймер не сбрасывается. Текущий зелёный
никогда не переходит прямо в конфликтующий. STOP/ERROR/потеря связи —
аварийное закрытие зелёных, без ожидания обычного жёлтого; открытие после
этого возможно только после нового HELLO/SYNC и полного красного интервала.
Ардуино проверяет интервалы через unsigned-разности millis(), включая wrap.
Лампы выводятся из одного enum, произвольной GPIO-команды нет. Сначала
выключаются прежние GPIO, затем зажигается новое допустимое сочетание.

Получение некорректной команды переводит прошивку в закрытое состояние,
выдаёт `ERROR,<reason>` и требует HELLO. Причины: TIMEOUT, PARTIAL_LINE,
INVALID_LINE, FORMAT, SEQUENCE, MODEL_TIME, TRANSITION, COMMAND, HELLO_REQUIRED.
Буфер — 96 байт (максимум 95 символов до LF); переполнение немедленно закрывает
зелёные и отбрасывает остаток строки. Незавершённая строка после 500 мс также
отклоняется. Пустые строки не продлевают watchdog. За loop обрабатывается
максимум 32 входных байта, поэтому непрерывный мусор не блокирует кнопку.

## Heartbeat, потеря связи и кнопка

Браузер посылает PING примерно каждые 500 мс, если нет ожидающей команды.
Если **2500 мс нет принятого сообщения**, питаемая Arduino устанавливает
четыре RED и PED_RED, блокирует дальнейшие STATE до HELLO/SYNC.
Браузер снимает аппаратную синхронизацию при отсутствии свежего Python-снимка
более 3 с, ответе Python дольше 1500 мс, изменении revision, пропуске шага,
неверном ACK, закрытии USB или скрытии вкладки. При разрыве без ACK интерфейс
показывает UNKNOWN, а не утверждает, что измерил ALL_RED.

A3: INPUT_PULLUP; нажатие LOW. Стабильный уровень 40 мс подтверждает изменение.
На одно нажатие передаётся `BUTTON,PED`, новое событие возможно после отпускания.
Кнопка не включает GPIO напрямую. Браузер передаёт событие всем моделям выбранной
сессии через `/api/sessions/{id}/pedestrian`; объединение запросов выполняет
существующий TrafficLight. В отключённом/несинхронизированном режиме кнопка
не создаёт запросов. Подтверждение доставки кнопки отдельно не реализовано:
при ошибке HTTP вывод останавливается и показывается ошибка, запрос можно повторить.

## Границы гарантий

ACK подтверждает работу прошивки, но не исправность LED/проводки. До setup(),
во время bootloader и при сбросе GPIO являются входами: программная защита
ещё не действует. При снятии USB-питания все лампы гаснут, «красный без питания»
не обещается. Watchdog здесь программный, не независимый аппаратный контроллер.
Это учебный макет, не сертифицированная система управления дорогой.

## Проверка без платы

```bash
g++ -std=c++11 -Wall -Wextra -Werror hardware/simulator.cpp -o /tmp/traffic-serial
pytest -q tests/test_hardware.py
arduino-cli core install arduino:avr
arduino-cli compile --fqbn arduino:avr:uno hardware/arduino/AdaptiveTrafficArduino
```

Host-симулятор использует тот же заголовок прошивки. В его stdin `@1234`
задаёт виртуальное millis(), `!1` нажимает кнопку, `!0` отпускает; остальные
строки — Serial. `PINS,<mask>,<phase>` — тестовый вывод, в USB-протокол не входит.
